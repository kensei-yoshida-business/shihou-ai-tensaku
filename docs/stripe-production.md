## 0. 全体の流れ

1. Stripe アカウントを本番利用できる状態にする（1章）
2. **テストモード**で商品・価格・Webhook を作り、Preview 環境で一通り試す（2〜3章）
3. **本番モード**で同じものを作り、Production 環境に登録する（2〜3章をもう一度）
4. カスタマーポータルと支払い方法を設定する（4・5章）
5. 本番で少額の実決済を1回通して確認する（6章）

テストモードと本番モードは、商品・価格・Webhook・API キーがすべて別々です。同じ作業を2回行います。

## 1. 本番利用の申請（アカウントの有効化）

- [ ] Stripe ダッシュボードで「本番環境の利用を開始」から事業者情報を登録する
  - 事業形態（個人事業主／法人）、代表者の本人確認、入金先の銀行口座
  - 事業のウェブサイト URL: 本番ドメイン
  - 商品・サービスの説明: 例「司法試験・予備試験の過去問答案のAI添削サービス（デジタルサービス、都度課金と月額課金）」
- [ ] **特定商取引法に基づく表記の URL** を登録する: `https://<本番ドメイン>/legal/tokushoho`
  - サイトの【要記入】欄（販売業者、所在地、電話番号、返金ポリシーなど）を先に埋めておくこと。審査で確認されます
- [ ] **明細書表記**（カード明細に出る名前）を設定する: 設定 → 公開ビジネス情報。ローマ字のほか、日本のカード向けに漢字・カナの表記も設定できます
- [ ] サポート用のメールアドレス・電話番号を設定する（領収書メールに表示されます）

## 2. 商品・価格（Price）の作成

`npm run stripe:setup` で、次の4つの価格と Webhook をまとめて作成できます。何度実行しても重複しません。

```bash
# テストモード（Preview 環境用）
STRIPE_SECRET_KEY=sk_test_... npm run stripe:setup -- https://<Preview に使うドメイン>

# 本番モード（Production 環境用）
STRIPE_SECRET_KEY=sk_live_... npm run stripe:setup -- https://<本番ドメイン>
```

実行すると、Vercel に登録する環境変数（`STRIPE_PRICE_*` と `STRIPE_WEBHOOK_SECRET`）が表示されます。

| 商品 | 金額（税込） | 種類 | 環境変数 | アプリ上の効果 |
|---|---|---|---|---|
| 添削チケット 1通 | 800円 | 一回払い | `STRIPE_PRICE_TICKET_1` | チケット +1。30日間 短答一問一答が無制限 |
| 添削チケット 5通パック | 3,600円 | 一回払い | `STRIPE_PRICE_TICKET_5` | チケット +5。同上 |
| スタンダード（月額） | 4,980円/月 | 継続（毎月） | `STRIPE_PRICE_SUB_STANDARD` | 月10通まで添削、短答無制限 |
| 無制限（月額） | 9,800円/月 | 継続（毎月） | `STRIPE_PRICE_SUB_UNLIMITED` | 添削・短答とも無制限 |

- 金額・通数は仮の値です。変える場合は `src/lib/stripe.ts` の `PLANS` を直してからスクリプトを再実行してください。Stripe の価格は金額を変更できないため、スクリプトが新しい価格を作り直し、表示される新しい Price ID を Vercel に登録し直します。
- 価格は**税込**（`tax_behavior: inclusive`）で作成します。
- ダッシュボードで手作業で作る場合も、上の表のとおりに作り、通貨は JPY、月額は「継続・毎月」にしてください。

## 3. Webhook の設定

スクリプトを使うと自動で作成されます。手作業で作る場合は次のとおりです。

- [ ] 開発者 → Webhook → エンドポイントを追加
  - URL: `https://<本番ドメイン>/api/webhooks/stripe`
  - 送信するイベント（この8つ）:
    - `checkout.session.completed`
    - `checkout.session.async_payment_succeeded`
    - `customer.subscription.created`
    - `customer.subscription.updated`
    - `customer.subscription.deleted`
    - `charge.refunded`
    - `charge.dispute.created`
    - `charge.dispute.closed`
  - **API バージョン**: アプリの Stripe SDK と同じ `2026-09-30.endive` を選ぶ。異なるバージョンだとイベントの形式が変わり、サブスクの反映に失敗することがあります（スクリプトは自動で合わせます）
- [ ] 表示された**署名シークレット**（`whsec_...`）を Vercel の `STRIPE_WEBHOOK_SECRET` に登録し、再デプロイする
- [ ] テストモードでは、Preview の Deployment Protection が有効だと Webhook が届きません。保護をバイパスする設定を使うか、テスト用のドメインを保護対象から外してください

アプリ側の動き（実装済み）:

- 署名を検証し、偽のリクエストは 400 で拒否
- 同じイベントが再送されても二重にチケットを付与しない
- 処理に失敗したら 500 を返し、Stripe の自動再送で再処理される
- チケット購入を返金すると、返金額に応じてチケットを自動で取り消す（7章）

## 4. カスタマーポータル（解約・カード変更）

会員情報ページの「プランの変更・解約・カード変更」ボタンから開く画面です。**本番・テストの両方で有効化が必要**です。

- [ ] 設定 → Billing → カスタマーポータルを有効にする
- [ ] 許可する操作:
  - [ ] 支払い方法の更新: 許可
  - [ ] 請求履歴の表示: 許可
  - [ ] サブスクリプションのキャンセル: 許可、「**請求期間の終了時**にキャンセル」を選ぶ（アプリは期間終了まで利用可能と案内しています）
  - [ ] プランの切り替え（任意）: 許可する場合は、スタンダードと無制限の2つの価格を選択肢に登録する。切り替えはアプリに自動で反映されます
- [ ] 利用規約・プライバシーポリシーの URL を登録する（`/legal/terms`、`/legal/privacy`）

## 5. 支払い方法

決済画面に出す支払い方法は、コードではなくダッシュボードで管理しています（設定 → 支払い方法）。

- [ ] **カード**: 有効（必須）
- [ ] **Apple Pay / Google Pay**: 有効にすると、スマホでの購入が簡単になります
- [ ] **コンビニ払い**（任意）: チケットの購入にだけ使えます（月額プランには使えません）。支払いが完了した時点でチケットが付与されるよう、アプリは対応済みです
- [ ] 不要な支払い方法は無効にしておく

## 6. 本番での最終確認

- [ ] Production の環境変数が `sk_live_...`、本番用の `whsec_...`、本番モードの Price ID になっている（テスト用の値が混ざっていない）
- [ ] 自分のカードでチケット1通（800円）を購入し、数秒でヘッダーの残チケットが増える
- [ ] Stripe ダッシュボードの Webhook 画面で、配信が成功（200）になっている
- [ ] 実際に添削を1回実行する
- [ ] 確認後、ダッシュボードから自分の決済を返金する（下記の注意も参照）

## 7. 運用上の注意

- **返金はダッシュボードから行うだけで、アプリ側の調整は不要です。** チケット購入を返金すると、Webhook で自動的にチケットが取り消されます。
  - 全額返金: 購入したチケットをすべて取り消し
  - 一部返金: 返金額に応じた枚数を取り消し（端数は切り上げ。例: 5通パック 3,600円のうち 720円を返金 → 1枚取り消し）
  - 既に使ったチケットを返金した場合、残数はマイナスになり、次に購入した分から差し引かれます（画面上は「0枚」と表示し、会員情報ページで理由を説明します）
  - 返金されたチケット購入は、短答一問一答の30日間無制限の対象からも外れます
- **チャージバック（不正利用の申し立て）** を受けると、その購入のチケットを自動で取り消します。勝訴した場合は自動で戻します。証拠（ログイン日時、添削の実行履歴）はダッシュボードから提出してください。
- **月額プランの返金**は、チケットとは関係なく Stripe のサブスクリプションの状態で利用可否が決まります。返金と同時に利用を止めたい場合は、ダッシュボードでサブスクリプションを「今すぐキャンセル」してください（キャンセルは自動でアプリに反映されます）。
- 月額プランの請求に失敗すると、Stripe は自動で再請求します。最終的にキャンセルされると、Webhook 経由でアプリ側のプランも無効になります。ダッシュボードの「Billing → 回収の管理」で再試行の回数と、失敗時に送るメールを設定してください。
- API キーは **制限付きキー**の利用も検討してください。アプリが使う権限は Checkout Sessions、Customers、Billing Portal、Webhook の検証だけです。
